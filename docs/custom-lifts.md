# PR47 — Custom movable-cannon designs

Select a linear or quadratic cannon in the Level Workshop and enable **Broken cannon · movable platform**. The initial y-position is rounded to an integer and clamped to the rail. Set lowest and highest integer stops and a locked global-x polynomial with zero constant, then Apply lift settings. Examples: `-x/2` or `-x^2/2+6x`. The current full equation is shown read-only. A lift can be the starting cannon, fire either direction, and coexist with any ordinary cannon family. Disable the lift to change its family. Dragging a lift in the workshop changes its authored x and initial snapped y; playing only changes y. Amber rails and decks show which objects are movable. Rails are non-solid; actual illegal placements are rejected by the simulator.

Only the authored shape, limits, and initial geometry are saved. Standard files remain byte-compatible version 1; files containing lifts use version 2 so older clients cannot silently strip the new mechanic. Both versions import, with validation of integer stops, edge clearance, shape/family, and bounded parsed coefficients. No entered equations, solved positions, certificates, or progress are exported. Existing version-1 local library keys and records remain valid; lift data is included in design identity and editing it invalidates the prior test, confirmation and records.

A custom test/play run uses immutable canonical design identity and a separate live layout. The store reconstructs the allowed y-only changes against the canonical level, validates them, and checks each actual reached leg's source and capture point; moved starting cannons and intermediate lifts can therefore legitimately complete. Confirmation still requires the current revision's completed successful Cadet playtest, including every Pip's arrival. Playback never changes authored initial positions. Imported designs must pass their own local playtest before confirmation.

Library cards and thumbnails indicate movable platforms and search recognises lift, movable and broken cannon. Tests cover serialization compatibility, malformed imports, moved-start/intermediate completion, invalidated proof, mode-specific records and the end-to-end workshop browser journey.
