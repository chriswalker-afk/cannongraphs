# PR8 — Multi-cannon routing

The mathematical engine resolves each leg to the nearest forward marked cannon or exit coordinate, unless a solid obstacle is contacted first (including a tie). Only the firing cannon is excluded from capture. Capture is not based on decorative artwork; numeric tolerances remain as in PR5. Identical anchors and the reserved exit ID are rejected by level validation. A route uses a complete snapshot of every parsed linear equation and stops on its first failure or exit. Returning to a visited cannon is a loop failure, preventing endless animation. One Pip/attempt is counted for the whole journey, not each cannon. A source mismatch at any stage uses the local disappointed misfire animation; previously travelled legs remain visible. The test Pip shrinks into the receiving cannon, then loads and fires again with the next equation. No future leg or angle is revealed while planning. Successful rapid-fire replays the entire route in a pipeline with per-cannon recoil, short capture/loading transitions and final-exit-only arrival counting. No diagonal shortcut between legs.

The original First flight remains available. A second preview, Cannon relay, is selectable. For PR8, a compact cannon selector reuses the existing editor with a saved draft per cannon, and launch requires every draft to be valid. All are locked during attempts and celebrations. PR9 will replace the selector with the dedicated all-cannon planning interface and tested-state indicators. Switching levels resets the unsaved run; no persistent progress yet. Relay terrain is intentionally simple: a low wall blocks the direct single-line shortcut; both intended legs are clearance-checked by automated tests.
