# PR31 — Physically supported cannons and exits

All playable cannons and exits use a visual mounting plan derived from their exact authored coordinates and the existing solid terrain. The cannon deck meets the rearward footprint below its muzzle; the exit deck meets the bottom of the door below its capture point. Leftward cannons mirror their footprint. The shared artwork dimensions are in src/game/anchorArtGeometry.ts.

The usual mount is an open tapered frame connecting a thin deck to the top of a nearby authored ledge. It is not an additional solid platform. Long gaps use open braces instead of opaque columns. Authored perches have priority because their original vertical clearances were deliberately chosen to protect steep trajectories. A wall bracket may be explicitly attached to an adjacent real wall. A suspension can attach to the underside of a real ceiling or to mounting plates at the upper background boundary, with hangers beside rather than through the body. The factory's elevated Cube drive exit has no nearby perch, so it uses a suspended cradle; the Temple relay's C cannon uses a wall-mounted bracket on the adjacent lower wall.

All mounts use world-specific material palettes. Draw them in a dedicated decorative layer behind the grid, actual terrain, waiting crew, cannons, gems, exit and flight traces. Light open framework is distinct from opaque, inspectable collision terrain; no new hitbox, platform, route requirement or inspection target. Supports never rotate with a barrel. The hover cosmetic receives a magnetic docking accent on the same stationary deck. Mathematical anchors, obstacle rectangles, reference equations, scores, mode rules and progress remain unchanged.

Support overrides are optional per-object metadata on Level (cannon ID or exit). Unknown object/terrain IDs and invalid wall overrides fail validation. The geometry resolver requires feasible attachment points, never changes the Level object, and uses no reference answers. A future level that cannot fit a mount must be authored explicitly rather than silently moving its cannon or exit.

Audit: npm run audit:supports prints one row for every level and each object's support kind and terrain attachment. The regression suite checks every resolved deck/contact, attachment and cosmetic, and the existing 72-route / 216-mode test remains intact. Chromium tests exercise grounded, elevated, suspended, wall-mounted, reverse-firing and multi-cannon scenes, resize/zoom and representative screenshots. Visual taste, real-device readability and any future genuinely collidable terrain redesign remain separate manual checks.
